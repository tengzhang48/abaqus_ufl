# Lessons on performance and parallel hosts

These are decision rules, with checks that can disprove a proposed speedup.
The [runtime API](../../abaqus_ufl/fe/README.md) owns supported calls and limits.

## Measure the representative bottleneck

Changing a host language does not change a direct factorization's complexity.
Profile assembly, matrix functions, scatter and solve separately at a state
that activates the claimed nonlinear branch. A cheap elastic U=0 call can be
dominated by Python overhead while the real path is constitutive-compute bound.
Re-profile after each improvement: accelerating the solve can expose assembly,
and batching can expose sparse insertion. Check wall time, memory and Krylov
iterations on the same problem before attributing an improvement to a rewrite.

For the public Ogden example, the reproducible measurement and its scope live
in [the API guide](../API_USAGE.md#generate_umat). Tiny MPI examples establish
correctness and overhead; they do not establish strong scaling.

## Perturb only active columns

A 2D plane-strain assembly uses four entries of F. Computing all nine tangent
columns repeats expensive constitutive work that assembly discards. Keep the
full 3x3 tensor, including F33=1, and perturb only active entries; initialize
unused derivative columns deterministically. The same reasoning removes the
third gradient perturbation in a 2D UEL. State updates used by stress remain
part of the tangent; output-only updates can be omitted only when dependencies
and side effects are understood.

Check active tangents against a nine-perturbation calculation at distorted,
nontrivial coupled states, including old state. Check residual, committed
state and PNEWDT as well, and prove the calls were accepted. The compiled
[2D regressions](../../tests/test_2d_tangents.py) also pin full 3D generated bytes.
The [pivot record](../pivots.md#p1-in-plane-complex-step) explains this change.

## Exact reuse needs complete inputs and state ownership

Newton residual checks, line search and commit can request the same element
batch. An exact snapshot cache can eliminate that work without approximating
the constitutive law. Its key must include every variable kernel input and
module identity, including committed state, properties, IDs and increment
metadata. A caller's in-place edit or mutation of a returned array must not
alter the saved entry. Required external side effects make reuse unsafe.

Check cache-on/off equality, actual evaluation counts, all key inputs,
nonfinite/rejected output, and commit/rejection invalidation. In MPI, every
rank must agree to a hit before skipping collectives; one missing entry or a
disabled cache forces every rank to evaluate. Empty partitions must vote too.
See [cache regressions](../../tests/test_fe_batch_cache.py) and
[MPI failure probes](../../tests/mpi_fe_contract.py).

## Keep replicated batching distinct from distributed algebra

Partitioning element evaluation does not distribute the mesh, state, global
matrix or linear solve. A root solve plus gathered batches is useful for
small verification jobs. Distributed MPIAIJ assembly and owned/ghost vectors
remove different bottlenecks. Even that host may gather final output or retain
replicated convenience inputs. State exactly which arrays and operations are
distributed before making memory or scaling claims.

Check results across rank counts against serial and an independent oracle.
Include a nonsymmetric tangent so storage-order transposition cannot hide;
make arrays contiguous for the consumer's layout. Exercise rank-local errors,
cutbacks, failed convergence and empty partitions before trusting success-only
parallel tests. No rank may raise before the shared error vote finishes.

## Diagnose the MPI environment before the algorithm

The launcher and Python bindings must use compatible MPI libraries. A launcher
or ABI problem observed on one machine is not a universal vendor limitation.
These public hosts use PETSc collectives, so mpi4py is optional. When both
bindings are used elsewhere, verify that they link compatible MPI builds.
Two-rank agreement alone cannot support claims about larger reduction trees
or decompositions; test the intended rank counts.

Also measure ranks multiplied by threads. Threaded BLAS or a direct solver on
every rank can oversubscribe the machine and make more ranks slower. Set the
thread budget deliberately and repeat the timing before diagnosing scaling.

## Separate convergence scales from preconditioning

A large mechanical residual can hide a small transport block in one global
norm. Check each field relative to its own physical scale and inspect both
residual and solution error. The small public hosts use a global relative
residual; a strongly disparate coupled model needs additional field-wise
certificates. Equation scaling changes convergence measurements and matrix
conditioning in different ways; document both.

Diagnose FieldSplit with exact block sub-solves before tuning AMG. Strong
two-way coupling may need a Schur split, while a degraded within-block stiffness
contrast can defeat AMG even after row scaling. An inexact linear tolerance
needs a fresh nonlinear residual check. Do not infer a solver's suitability
for an indefinite coupled problem from a scalar Poisson scaling result.
